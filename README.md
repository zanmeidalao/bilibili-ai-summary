# B站AI总结助手（Chrome 扩展）

在 B 站页面生成一个**可拖拽的悬浮按钮**，点击即可一键复制当前视频的字幕，并可**自动发送到当前标签页右侧的 AI 聊天框**。

- 适配普通视频页（`/video/BV...`）
- 字幕语言优先级：**中文 → 英文 → 其他**（自动选择，无需手动挑选）
- 复制格式可切换：纯文本 / 带时间戳 / SRT
- **发送到右侧 AI**：复制后自动激活右侧标签页，把字幕填入 AI 输入框（开关见下方说明）

## 安装

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车
2. 打开右上角「开发者模式」开关
3. 点击「加载已解压的扩展程序」
4. 选择本文件夹 `bilibili-ai-summary`（含 `manifest.json` 的那个目录）
5. 打开任意 B 站视频页，页面会出现粉色悬浮按钮

> - 需要 Chrome 88+（Manifest V3），推荐 Chrome 111+（字幕 JSONP 兜底依赖 `scripting` 能力）
> - **每次更新插件文件后**，在 `chrome://extensions/` 点该扩展卡片上的「**重新加载**」按钮，再刷新 B 站页面
> - 若 AI 标签页是在安装扩展**之前**打开的，需要先刷新一次该 AI 页面（让注入脚本生效）

## 使用

| 操作 | 效果 |
| --- | --- |
| **左键点击按钮** | 复制当前视频字幕到剪贴板；若「发送到右侧 AI」开启，还会自动发送到右侧标签页 |
| **右键点击按钮** | 弹出**控制面板**：复制格式、发送到右侧 AI 开关、AI 模型、AI 对话标签、字幕语言、下载清晰度、分析提示词（含「管理」入口） |
| **按住拖动按钮** | 调整按钮位置（位置会记住） |

> **注意**：右键面板是独立的，**不会**同时触发左键的复制功能。

复制成功后按钮上方会弹出提示，显示复制了多少条字幕、用了哪种语言。**复制内容会把视频标题拼在最前面**，例如：

```
【全球最过誉的五个学说】
大家好，欢迎收看本期节目
```

格式示例（同一段字幕的三种输出）：

- 纯文本：`大家好，欢迎收看本期节目`
- 带时间戳：`[00:03] 大家好，欢迎收看本期节目`
- SRT：
  ```
  1
  00:00:03,000 --> 00:00:06,000
  大家好，欢迎收看本期节目
  ```

## 发送到右侧 AI

开启后（按钮右上角会出现绿色 **AI** 角标），点击按钮的完整流程：

1. 抓取字幕，在末尾**自动追加一段分析提示词**（要求 AI 概括内容、高亮重点、对比数据、总结作者立场等）
2. 复制该完整文本到剪贴板（所见即所得：剪贴板里就是你发给 AI 的内容）
3. 自动扫描**当前窗口全部标签页**找受支持的 AI 站点，决定目标标签页：
   - 已打开且正是**所选模型**（如选了元宝且已开元宝）→ 直接复用该标签
   - 已打开的 AI 站点与所选**不一致** / 完全没有受支持站点 → 在右侧**自动新建**所选模型的标签页（默认行为，无需手动开关）
4. 激活目标标签页，由 AI 页脚本在本页内把字幕写入输入框并点击「发送」按钮（无需你手动操作；不依赖浏览器调试器，不会出现调试提示条）

> 提示词只有在「发送到右侧 AI」开启时才追加；关闭后仍只复制原始字幕。

### 开关方式

右键点击悬浮按钮 → 面板中「**发送到右侧 AI**」开关（开启时显示绿色状态）→ 点击即可开/关（带 ✓ 表示开启）。设置会被记住。

### 使用前提

- 想发送到的 AI 页面**已在当前窗口打开**（自动复用），或允许**自动新建**（默认：点击发送时若右侧没有符合条件的 AI 标签页，会在右侧自动新建一个所选站点标签页并发送，等它加载就绪后再把字幕发过去）。
- 自动新建的标签页需要你自行登录对应 AI 站点；若加载超时（约 15s）或登录态缺失，会提示失败而不卡死。

### AI 模型选择

右键点击悬浮按钮 → 面板「**AI 模型**」下拉，可设置默认目标站点（列出全部受支持站点，按地址自动显示中文名，如 ChatGPT / DeepSeek / Kimi / 文心一言…；当前选中项显示在面板上）。

- **默认站点**：从未手动选择时，自动新建默认打开 **DeepSeek**（chat.deepseek.com）；手动选过之后以你的选择为准。
- 新建的标签页插在当前 B 站标签页右侧一格，与「右侧标签页」模型一致，后续手动点击也照常工作。
- 站点库来源于 `manifest.json` 中 `ai-content.js` 注入的域名 + `shared.js` 的中文名映射；新增站点只需在 manifest 加域名并在 `shared.js` 的 `AI_SITE_NAMES` 补中文名，下拉会自动出现。

### AI 对话标签（新建对话 / 沿用对话）

右键点击悬浮按钮 → 面板「**AI 对话标签**」下拉，可切换发送时的标签页策略：

- **沿用对话（默认）**：右侧已有与所选模型一致的标签页则复用；否则按默认行为在右侧自动新建。
- **新建对话**：每次点击图标都**新建一个**右侧标签页打开所选模型并发送，不论右侧是否已有该模型的标签页。

> 若连续点击图标，新建对话模式会依次打开多个标签页，请按需关闭。

### 关于「当前视频」的识别与防误发

复制字幕时，以**页面 URL 的 bvid 为唯一视频标识**（用户正在看的视频页）。为避免「灰度状态滞后」导致的误发，点击按钮时会用**与后续抓取同一时刻的 URL 实时复检**当前视频字幕列表：

- **有字幕** → 恢复彩色并继续完整流程（复制 + 可选发送到右侧 AI）；
- **无字幕 / 检测失败** → 仅提示「该视频暂无字幕」，**绝不复制、不发送、不跳 AI**。

闸门与抓取使用同一时刻的 URL，二者永远一致，不会出现「图标是灰的却仍抓取/跳 AI」的错位。若识别不到视频（非视频页），提示「视频无字幕或识别失败，请刷新重试」。

> 说明：B 站 SPA 自动连播 / 页内换源时，地址栏 URL 会滞后几秒才更新。本方案不额外做播放器交叉校验，而是让「点击时的闸门」与「抓取」同源，简单且行为可预期；URL 仍滞后期间若恰好指向一个有字幕的视频，会如实复制该视频字幕（属预期的取舍，不再纠缠跨视频根因）。

### 无字幕时图标灰度

**进入视频页时按钮默认即为灰度（desaturate + 半透明）**；扩展自动查询该视频是否有可用字幕文件，有字幕才恢复彩色，无字幕则保持灰度，直观提示当前视频不可用。查询失败（未登录 / 网络异常）按「无字幕」灰显。切到新视频（SPA 路由变化）时会重新检测。灰度仅为视觉提示，真正的「无字幕拦截」由点击时的实时复检决定（见上）。

## 下载视频（清晰度可选）

右键点击悬浮按钮 → 面板「**下载视频**」按钮，即可把当前视频自动保存到浏览器的**默认下载目录**（不弹窗选择位置，自动静默下载）。

- 右键面板「**下载清晰度**」下拉可指定目标清晰度：**1080p（默认，最高）/ 720p / 480p / 360p**；默认即为最高清晰度 1080p，优先用该清晰度，失败再按 1080→720→480→360 自动回退（1080p 取决于账号登录态 / 大会员，取不到时降级，保证下得下来）。面板上会实时显示当前选中的清晰度
- 多分片自动合并为一个 mp4；文件名以视频标题命名（非法字符已清洗），保存到「下载/…/bilibili视频/」子目录
- 视频流 CDN 若返回 403，会自动依次尝试多种防盗链请求头组合（Range+Referer / 仅 Range / Range+Origin / 带 Cookie），无需手动干预；首个成功的组合会被缓存，后续分段直接复用
- **并发提速**：大分片自动按 4MB 切成多段，同时 5 路并发拉取（Range 分段），明显快于单线程串行下载
- 下载全程有**实时进度条**：流式拉取，边下边更新（「分片 x/N · xx.xMB」），落盘阶段显示「正在写入磁盘…」
- 需要登录 B 站（获取带签名播放地址的前提）

### 支持的 AI 站点

ChatGPT（chatgpt.com / chat.openai.com）、Claude（claude.ai）、Gemini（gemini.google.com）、Google AI Studio（aistudio.google.com）、DeepSeek（chat.deepseek.com）、Kimi（kimi.moonshot.cn / www.kimi.com）、智谱清言（chatglm.cn）、通义千问（chat.qwen.ai / tongyi.aliyun.com）、豆包（doubao.com）、文心一言（yiyan.baidu.com / chat.baidu.com）、Grok（grok.com）、Perplexity（perplexity.ai）、Copilot（copilot.microsoft.com）、Mistral（chat.mistral.ai）。

> 不在列表里的站点暂不支持（避免误填入无关页面）。如果右侧标签页不是 AI 站点，或右侧没有标签页，会保留已复制的字幕并给出提示，不会破坏原操作。

### 已知限制

- 右侧标签页若被浏览器休眠（Discarded），激活后需要短暂等待其重新加载，插件会自动重试（约 2 秒），一般无需干预。
- 发送时插件在 AI 页面内直接写入字幕并点击「发送」按钮，**不附加调试器**，因此不存在调试器相关限制，也不需要关闭 F12 开发者工具。
- 首次安装扩展时，已经打开的 AI 标签页里还没有注入脚本，发送会失败——**刷新一次该 AI 页面即可**。
- 各 AI 站点页面改版可能导致输入框或「发送」按钮选择器失效；此时发送会提示「未找到聊天输入框」或点击发送无反应，可在评论区/Issue 反馈，或在 `ai-content.js` 的 `HOST_SELECTORS` / `SEND_SELECTORS` 中补充对应选择器。

## 字幕优先级

自动从接口返回的字幕列表里挑选，规则：

1. 语言代码 `ai-zh` 或 `zh` 开头（中文，含自动生成中文字幕）
2. 语言代码 `ai-en` 或 `en` 开头（英文）
3. 其余任意语言（如 `ja-JP`、`ko-KR` 等）

## 字幕语言选择

右键点击悬浮按钮 → 面板「**字幕语言**」下拉：

- **自动**：沿用上面的中 → 英 → 其他 优先级（默认）
- **具体语言**：列出该视频实际存在的字幕语言（如「中文（自动生成）」「English」「日本語」等），选中后只复制该语言

设置会被记住；下次复制直接生效。某语言该视频没有时，复制会提示「该视频没有 XX 字幕」，改回「自动」即可。

## 设置页（分析提示词管理）

右键点击面板中「分析提示词」行的**「管理」**按钮，或扩展管理页（`chrome://extensions`）中本扩展的「**选项 / 扩展选项**」打开设置页（提示词管理页）。

### 分析提示词（可管理列表，单选当前生效）

- 内置「**默认分析**」项：即插件自带的那段长提示词，**不可删除、不可改名、内容不可编辑**，仅可停用或选为当前（保证永远有兜底）。
- **新增提示词**：点击页面顶部醒目的**粉色「＋ 新建提示词」按钮**添加自定义项，填写名称与正文，可随时编辑。
- **删除提示词**：自定义项右侧有「删除」按钮（内置项无删除按钮）。
- **单选当前生效**：每条前有「选为当前」单选；同一时刻只有一条生效（或选「不使用提示词」完全不带）。当前选中的项会在复制并发送到右侧 AI 时，追加到字幕末尾。
- 在 B 站页面**右键悬浮按钮 → 面板「分析提示词」下拉**也能快速切换当前项，无需进设置页。下拉列表顺序与设置页完全一致（首项为「不使用提示词」）。

### 保存与生效

- 设置页上的编辑属于**暂存**状态，需要点击页面底部的**「保存」按钮**（或按 **Ctrl / Cmd + S**）才会真正写入并生效。
- 存在未保存改动时，页面顶部/底部会显示粉色「**● 未保存修改**」提示，保存按钮呈脉动高亮；保存成功后转为绿色「**✓ 已保存**」并自动置灰。
- 存在未保存改动时如果直接关闭或刷新页面，会弹出离开确认，防止误操作丢失内容。
- 保存成功后，改动立即对所有 B 站页面生效。

## 技术要点（为什么这样设计）

- **网络请求全部在 Service Worker 中发起**：SW 的 `fetch` 拥有 `host_permissions`，Chrome 会**绕过 CORS 响应检查**——因此即使 `api.bilibili.com` / `aisubtitle.hdslb.com` 不返回 `Access-Control-Allow-Origin` 头，也能正常读取响应（content script 直连会被 CORS 拦截，报 `Failed to fetch`）。同时扩展上下文可以设置 `Referer` 请求头，B 站接口依赖该头；请求不带页面 Origin，不会触发 B 站 412 风控。
- **字幕内容**：优先 SW `fetch`；失败时回退到页面主世界 `<script>` 标签 JSONP 加载（`window.__SubtitleJSONP__`，与 B 站播放器同款机制）。
- **视频识别只认当前 URL 的 BV 号**：cid 一律由 `view` 接口按 BV 号实时解析。**不依赖** `__INITIAL_STATE__`、`__playinfo__`、`oid` 等可能残留「上一个视频」数据的来源，避免复制到别的视频的字幕。
- **视频下载**：`view` 拿 cid → `x/player/wbi/playurl`（带 `platform=html5` 拿播放器同款 CDN 节点）拿带签名 durl → 交给 **offscreen document** 拉取分片（离屏页面有 DOM，能生成 blob URL；MV3 Service Worker 无 `URL.createObjectURL`）→ 分片合并成 blob → `chrome.downloads` 落盘 → `chrome.downloads.onChanged` 把落盘进度推回页面显示进度条。需要 `downloads` + `offscreen` 权限与 `*.bilivideo.com` 等 host 权限（见 manifest）。
- **发送到 AI 的链路**：B 站页 → background（`chrome.tabs` 找右侧标签页并激活）→ AI 页 content script（`ai-content.js`）在本页内完成字幕写入与发送：聚焦输入框 → 分段用 `document.execCommand('insertText')`（contenteditable 富文本编辑器可识别，无需调试器）或原生 `value` setter + `input` 事件（React 受控 textarea 兼容）写入字幕 → 点击「发送」按钮（各站点见 `SEND_SELECTORS`，兜底派发 Enter）。**全程不使用 `chrome.debugger`**，因此不会触发「插件已开始调试此浏览器」横幅。

## 注意事项

- **需要登录 B 站**：字幕列表接口现在要求登录态（cookie），请在已登录状态下使用。
- 视频本身**没有 AI/CC 字幕**（如纯音乐、无人声、竖屏故事视频等）时，会提示「该视频暂无字幕」。
- 网络偶尔被 B 站限流/风控时会提示重试，稍候再点即可。

## 文件结构

```
bilibili-ai-summary/
├── manifest.json          # 扩展清单（MV3）：tabs/downloads/offscreen 权限 + B 站 / AI 站点注入 + 视频 CDN host
├── background.js          # Service Worker：全部网络请求 + wbi 签名 + 字幕抓取 + 右侧标签页查找/发送 + 下载协调/进度转发
├── content.js             # B 站页：悬浮按钮 UI、右键控制面板、BV 号提取、格式化、复制、下载入口、进度条
├── ai-content.js          # AI 页：在本页内定位输入框、写入字幕并点击「发送」按钮（不使用调试器）
├── offscreen.html/js      # 离屏页面：视频流分片拉取 + 防盗链重试 + blob 合成（SW 无 DOM，需在此生成 blob URL）
├── options.html/js        # 提示词管理页（分析提示词列表的增删改与当前项选择、保存）
├── shared.js              # content.js 与 options.js 共享的常量与工具（DEFAULT_AI_PROMPT、escapeHtml、normPrompt）
├── icons/                 # 扩展图标（16/32/48/128）
└── README.md
```

## 隐私

- 只向 `*.bilibili.com`、`*.hdslb.com`、`*.bilivideo.com` 等 B 站及其视频 CDN 发起请求（获取视频信息、字幕、视频流）
- 视频下载仅在**你点击面板里的下载项**时发起；下载内容只落到你自己浏览器的下载目录
- 字幕文本只发送到**你自己打开的右侧标签页**（本机浏览器内传递），不上传任何第三方

## 代码架构（开发向）

- `content.js` / `options.js` 共享的常量与工具（`DEFAULT_AI_PROMPT`、`escapeHtml`、`normPrompt`）统一放在 **`shared.js`**，由 manifest 的 `content_scripts` 与设置页 `<script>` 共同加载，避免两端重复定义导致漂移。
- **受支持的 AI 站点列表**（`AI_HOSTS`）不再手写在 `background.js`，而是在运行时从 `manifest.json` 中 `ai-content.js` 的 `content_scripts.matches` 自动派生——新增 AI 站点只需改 manifest 一处。
- 字幕请求 `getSubtitle` 与 `getSubtitleLangs` 共用 `fetchVideoView()`，消除重复的 view→cid→取字幕列表逻辑。
- 视频下载进度上报已做节流（≥200ms 一次），多任务按 `requestId` 各自独立节流，避免大文件或并发下载产生大量跨上下文消息卡顿。
- 网络请求 `getJson` 对 4xx 客户端错误（风控/无字幕）直接抛出、不重试；仅 5xx 才重试。

## 基于 GitHub 的更新

本扩展以「解压版」方式安装，无法像商店版那样静默自更新。因此内置了一套**基于 GitHub 仓库的更新检测**：

- 仓库根目录维护 `version.json`，含最新 `version` / `notes` / `date`；
- 后台（`updater.js`，由 `background.js` 经 `importScripts` 注入）在**安装时**及之后**每 12 小时**（经 `chrome.alarms`）自动 `fetch` `raw.githubusercontent.com` 上的 `version.json`，与 `manifest.json` 的 `version` 比对；
- 发现新版本时：悬浮按钮出现橙色 `↑` 角标、右键面板「更新」行显示「当前 → 最新」、选项页「关于/更新」同步提示；
- 点「下载更新」会拉取最新版源码 zip（`https://github.com/<仓库>/archive/refs/tags/vX.Y.Z.zip`）到下载目录，解压覆盖原文件夹后到 `chrome://extensions` 点「重新加载」即可升级。

> 受 MV3 安全限制，扩展**不能自行替换文件**，所以更新需手动覆盖 + 重载；这是设计使然，非缺陷。

## 发版流程

1. 改 `manifest.json` 的 `version`（语义化版本，如 `3.0.1`）；
2. 同步改仓库根 `version.json` 的 `version`，并填写 `notes` / `date`；
3. 提交并打 git tag：`git tag vX.Y.Z`；
4. 在 GitHub 该仓库 **Releases** 页以该 tag 发布，上传源码 zip（tag 名须与 `version.json` 的 `version` 一致，扩展据此拼下载地址）；
5. 推送后，已安装用户将在 12 小时内（或手动「检查更新」）收到新版本提示。

> 首次发布前，请把 `updater.js` 顶部的 `UPDATE_REPO = 'OWNER/REPO'` 改成实际仓库路径（如 `alice/bilibili-ai-summary`）。
